# Git и GitHub — шпаргалка

Краткая памятка по работе с Git и GitHub для этого проекта (et90/miniGame).

## Что такое Git и GitHub

- **Git** — программа контроля версий на вашем компьютере: хранит историю изменений проекта.
- **GitHub** — облачный сайт, где лежит копия репозитория (бэкап + совместная работа).
- **origin** — имя удалённого репозитория: `https://github.com/et90/miniGame.git`

## Ежедневный цикл — «пятёрка»

```powershell
git pull                        # 1. взять свежие изменения с GitHub
#  ... редактируете файлы ...
git status                      # 2. посмотреть, что изменилось
git add -A                      # 3. подготовить изменения
git commit -m "Что я сделал"    # 4. зафиксировать снимок
git push                        # 5. отправить на GitHub
```

## Основные команды

| Команда | Действие |
|---|---|
| `git status` | что изменено прямо сейчас |
| `git diff` | показать изменения построчно |
| `git log --oneline --graph` | история коммитов |
| `git add файл` | подготовить один файл |
| `git add -A` | подготовить все изменения (новые, изменённые, удалённые) |
| `git commit -m "текст"` | создать коммит |
| `git push` | отправить коммиты на GitHub |
| `git pull` | забрать изменения с GitHub |
| `git clone <url>` | скачать репозиторий с GitHub |
| `git restore файл` | отменить незакоммиченные правки файла |
| `git reset --soft HEAD~1` | отменить последний коммит, правки оставить |

## Ветки (branch)

Зачем: `main` всегда должна оставаться рабочей, а эксперименты и новые фичи — в отдельных ветках.

| Команда | Действие |
|---|---|
| `git branch` | список локальных веток |
| `git branch -a` | список всех веток (включая удалённые) |
| `git checkout -b имя` | создать ветку и перейти в неё |
| `git checkout main` | переключиться на ветку main |
| `git merge имя` | влить ветку `имя` в текущую |
| `git branch -d имя` | удалить локальную ветку (после слияния) |
| `git push origin --delete имя` | удалить ветку на GitHub |

## Pull Request (PR)

PR — это предложение влить ветку в другую ветку (обычно в `main`), с просмотром и обсуждением изменений.

1. Запушьте ветку: `git push -u origin имя-ветки`
2. GitHub покажет ссылку «Create a pull request» (или вкладка **Pull requests → New**).
3. Проверьте изменения во вкладке **Files changed**, при необходимости оставьте комментарии.
4. Нажмите **Merge pull request** — изменения попадут в `main`.
5. После слияния ветку можно удалить.

Страница создания PR для текущей ветки `story-mode`:
https://github.com/et90/miniGame/pull/new/story-mode

## После слияния PR

```powershell
git checkout main                   # вернуться в main
git pull                            # подтянуть смерженные изменения
git branch -d story-mode            # удалить локальную ветку
git push origin --delete story-mode # удалить ветку на GitHub (необязательно)
```

## Пример: что делалось в этом проекте

```powershell
git status                                     # посмотрели, что изменено
git checkout -b story-mode                     # создали ветку сюжетного режима
git add -A                                     # подготовили все файлы
git commit -m "Add story mode with ..."        # зафиксировали (16 файлов)
git push -u origin story-mode                  # опубликовали ветку на GitHub
```

## Частые ситуации

- **`push` отклонён (rejected)** — на GitHub есть новые коммиты: сначала `git pull`, разрешите конфликты (если есть), затем `git push`.
- **Конфликт слияния** — Git пометит спорные места в файле маркерами `<<<<<<<`, `=======`, `>>>>>>>`; отредактируйте файл, затем `git add` и `git commit`.
- **Случайно изменили не ту ветку** — `git stash`, `git checkout нужная-ветка`, `git stash pop`.
- **Хочу отменить незакоммиченные правки** — `git restore .` (осторожно: правки исчезнут).

## Полезные привычки

- Осмысленные сообщения коммитов: «Add story mode…», а не «fix».
- Коммитьте часто и небольшими порциями.
- Перед началом работы — `git pull`.
- Никогда не коммитьте пароли и токены.
- Мусорные файлы (черновики, кэш) — в `.gitignore`.
- Регулярный `git push` — это ваш бэкап.
